01 Overview

Six websites. One panel.

The challenge

Content scattered across six sites

The agency runs several publishing brands, each with its own hand-built PHP website. Every new blog post, phone number or SEO tweak meant a developer editing files on that one site.

  • Writers couldn't publish without a developer.
  • Local SEO needed hundreds of "service in city" pages per brand.
  • The existing sites, designs and lead forms had to stay exactly as they were.
  • Different people needed access to different brands.
  • A panel outage must never take a brand website down.
The solution

A headless panel + a drop-in kit

A central Laravel + Inertia + React panel where the team writes everything, and a tiny PHP brand kit each website drops in. The kit adds /blogs, location pages and sitemaps, and renders them inside the site's own header and footer.

  • Block-based post editor with layouts, authors, SEO and custom schema.
  • States × cities × services generate every local page automatically.
  • Settings like phone and logo flow into the site's existing pages.
  • File cache on each site: it keeps serving even if the panel is down.
  • Admin / editor roles with per-brand access, enforced on the server.

02 How every brand links back

Plug a brand in, in six steps.

A brand website never changes its pages. It gets a small kit and a key, and from then on the panel and the site talk to each other.

  2. 1
    Panel · admin

    Create the brand

    Name, slug (used in API URLs), website URL and which blog layouts the site has. Writers later only see the layouts that brand actually supports.

  3. 2
    Panel · keys

    Get a key and a secret

    The panel issues an API key, shown once and stored hashed, and an encrypted cache secret. It prints a ready-to-paste cms/config.php, and both can be rotated with one click.

  4. 3
    Brand site · files

    Drop in the brand kit

    Copy blog.php, location.php, sitemap.php and the cms/ folder to the site root, paste the config and merge a few .htaccess lines. Only /blogs, location URLs and sitemaps are routed to the kit. Every existing page keeps working.

  5. 4
    Brand site · pages

    Wire the site's own pages

    Three small hooks: a config include gives variables like $phone their value from the panel (today's value as fallback), cms_head() adds SEO tags and site code, and cms_footer_code() closes the page.

  6. 5
    Panel ↔ site

    Test the connection

    One button calls the site's clear-cache.php with the secret and reports back. Then Find pages asks the site's cms/pages.php for its own page files, so their Google titles and descriptions become editable in the panel.

  7. 6
    Search engines

    Sitemaps join the dots

    /sitemap.xml becomes an index of the site's own pages, its blog and every location page, all generated. New posts, places and page files appear by themselves; point robots.txt at it once.

The brand API

Every call needs the brand's X-Api-Key; a paused brand or a wrong key gets 401.

GET /api/v1/{brand}/settingsname, URL, every setting, and SEO overrides for the site's own pages
GET /api/v1/{brand}/postspaginated post summaries (max 50 per page)
GET /api/v1/{brand}/posts/{slug}full post with blocks, SEO, schema · 301 for renamed slugs
GET /api/v1/{brand}/sitemapevery published slug + last modified
GET /api/v1/{brand}/locationsURL map, redirects, the states-and-cities menu, hub texts
GET /api/v1/{brand}/locations/{key}one state, city or service page with placeholders filled in

03 The panel

Built for writers, not developers.

A bold, playful interface I designed so non-technical writers enjoy using it. Pick a module:

Every brand's posts in one place

  • Live, drafts, scheduled and trash at a glance, with search, month and day filters.
  • Schedule posts with a future publish date; the API only returns them once that date passes.
  • Duplicate a post as a draft with a free slug, move it to another brand, or restore from trash.
  • Renaming a slug keeps the old URL alive with a 301 redirect.

Stack blocks, pick a layout

  • 9 block types: heading, paragraph, image, image + text, quote, call to action, two columns, gallery, FAQ.
  • 4 layouts (classic, hero, sidebar with table of contents, minimal), limited to what each site supports.
  • Per-post SEO title, description, share image and custom JSON-LD schema, validated and stored as data.
  • Authors written once per brand; the default writer box shows under every post.

Write once, publish everywhere

  • Add states and cities; each gets a page with banner, the site's own lead form, services, cities, FAQs and contact.
  • Services are templates: {location}, {city}, {service}, {brand} become real names on every page.
  • 3 states, 8 cities and 4 services already make 55 pages; any single page can override its text, FAQs or SEO, or be hidden.
  • Brand-wide page defaults and a /locations hub; renamed slugs redirect with 301.

One source of truth per brand

  • Contact details, logo, favicon, footer text and social links, read on the site with setting('phone').
  • Theme colours and fonts flow into the kit's pages as CSS variables, so they match each brand.
  • Site code for <head> and <body> (GTM, verification, chat widgets), with every change logged.
  • Pages & SEO: Google titles, descriptions, share images and "hide from Google" for the site's own pages.

Switch brands in one click

  • Every brand as a card with its posts, editors and active / paused state.
  • The brand switcher in the sidebar keeps writers in the right site.
  • Pausing a brand instantly stops its website from loading content (API answers 401).
  • A console import loads posts, authors, services, locations and settings from JSON when onboarding a brand.

05 Live on the brands

Their design. Our content.

  • Same header, footer and lead form as the rest of the brand site: the kit renders inside them.
  • Brand colours and fonts from the panel's theme, as CSS variables the site can still override.
  • Breadcrumbs, category, author box, reading time and "keep reading" on every post.
  • Full SEO in the HTML: title, description, canonical, Open Graph and BlogPosting schema.
  • Location pages fill the lead form with hidden fields, so each lead says which city and service it came from.
  • Promotions from config, like the Black Friday bar with a countdown that removes itself after the end date.

06 Under the hood

Small, fast and safe.

01

One app, no separate API to deploy

Laravel controllers render React pages through Inertia, with normal sessions and CSRF. Each screen is its own small JS chunk built with Vite.

02

React on Preact

React is aliased to Preact in Vite, so the whole app shell is about 55 kB gzipped and each screen adds 1 to 7 kB. The one missing React 19 API is shimmed.

03

Never down because of the panel

Brand sites cache every response as files for 10 minutes, keep serving the last copy if the panel is unreachable, and cache 404s for 60 s so bots can't hammer it.

04

Security by default

Hashed API keys, encrypted secrets, sanitized rich text and URLs, image-only uploads (no SVG), pasted schema that can never run as script, anti-framing headers.

05

Everything is logged

An activity log shows who created, changed, published or deleted what, on which brand, with the old and new value of every field.

06

Easy to run on shared hosting

No terminal needed: an admin-only maintenance page runs migrations, storage links and cache clears. New builds reload open tabs on their next click.
