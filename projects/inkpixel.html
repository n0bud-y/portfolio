01 Overview

Fast, findable, and editable.

The brief

A production-grade agency site

The studio needed a site that wins clients and that the marketing team can keep fresh. Targets were written down before a line of code:

  • Speed: LCP ≤ 2.5 s, INP ≤ 200 ms, CLS ≤ 0.1; Lighthouse mobile ≥ 90.
  • SEO: server-rendered HTML, valid structured data, Lighthouse SEO 100.
  • Accessibility: WCAG 2.2 AA.
  • Editors publish case studies and posts without a developer.
  • No lead ever silently lost; hosted on the company's cPanel server.
What I built

One Next.js app, two content sources

A Next.js 16 App Router site where static pages keep their copy in typed TypeScript files, while Contentful holds only what editors change often: case studies and blog posts.

  • Contentful read over GraphQL with plain fetch: no SDK, server-only, cached with tags.
  • Content types created by numbered migration scripts, never by hand.
  • Every env variable validated with Zod: a missing key fails the build, not the visitor.
  • Standalone Node server on cPanel, built on git pull, cached by Cloudflare.
  • Mega menus, popups, responsive layouts and GSAP motion: designed and built by me.

02 UI I designed & built

Menus, motion & micro-moments.

The home page and a few templates follow our designer's Figma. The rest, more than 60% of the interface, I designed and built myself:

Three mega menus, one engine

  • Services, Industries and Technologies share one MegaMenu frame and a useHoverMenu hook for open / close timing.
  • Category rail on the left, live preview on the right, "book a free call" in the footer.
  • Keyboard and screen-reader friendly: Industries and Technologies are real buttons, not fake links.
  • Links prefetch on hover, so the next page is ready before the click.

A stack browser in the header

  • Six groups (frontend, backend, mobile, databases, CMS & e-commerce, cloud) with real tech logos.
  • Each group shows its tools as logo tiles, with a "book a free call" prompt for anyone with a stack in mind.
  • On phones it folds into an accordion inside a full-screen menu.

A quiz that turns visitors into leads

  • Step-by-step questions with a progress bar, then contact details and an estimate request.
  • Ends in a custom "your estimate request is in" dialog: no page reload, no lost context.
  • Every enquiry is emailed and also written to a backup log, so none is silently lost.

A timeline that follows the scroll

  • Five phases from discovery to launch; the line draws and each phase lights up as you scroll.
  • Built on reusable motion components, not one-off animation code.

Industries, tabbed and reusable

  • Industries live as typed data, so the menu and the home tabs stay in sync.
  • The same section re-themes for light pages with a single tone prop.
  • Accessible tabs: arrow keys, Home / End, and inactive panels stay in the HTML for SEO.

How a case study is built

  • Hero layouts: split, centered or light, plus optional "hero layers" (floating screenshots) or a muted looping video.
  • Ordered sections: text + image, tech stack, cards, screens, SWOT, results, testimonials, gallery and video, in any order.
  • Automatic rhythm: sections alternate navy and white by themselves; hidden ones don't count.
  • Accent words: wrap a word in *asterisks* and it renders in the brand gradient.
  • Client safety: a client logo only shows once "logo use approved" is ticked; testimonials stay drafts until approved.
  • Reused everywhere: the same entries feed the work listing and the project cards on service pages.

05 Under the hood

Engineering I'm proud of.

01

Content model as code

Every Contentful type, from blog posts to case-study sections, comes from 19 numbered migration scripts. The model is reviewable, repeatable and never edited by hand.

02

No SDK, typed fetchers

A tiny server-only GraphQL client over fetch, with typed queries like getCaseStudy and getProjectCards, hourly revalidation and cache tags.

03

Fails safe, not loud

If Contentful is down or a type is missing, that one section hides itself and logs why; the rest of the page still builds and ships.

04

Crash-safe cPanel deploy

A git post-merge hook builds on git pull, and the app runs from a copied live/ server, so a build killed half-way no longer takes the site down. A low-memory build mode fits shared hosting.

05

Config that can't be wrong

Environment variables are validated with @t3-oss/env-nextjs and Zod. A missing or empty key fails the build instead of breaking a page for a visitor.

06

Prerendered, refreshed quietly

Pages are prerendered and refreshed in the background, and send s-maxage=3600 with stale-while-revalidate, so they are ready to be cached at the edge.
